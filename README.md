# OpenAI Limits для OpenCode

**Лимиты Codex и полные сбросы — прямо в правой панели OpenCode TUI.** Без переходов в личный кабинет и без смешивания квот OpenAI с квотами самого OpenCode.

```text
◈  OPENAI · ЛИМИТЫ

5 часов   65% осталось
━━━━┄┄┄┄┄┄  35%
До сброса: 2 ч 14 мин
Сброс: 02.11, 18:40

Неделя    20% осталось
━━━━━━━━┄┄  80%
До сброса: 4 д 3 ч
Сброс: 06.11, 19:00

↻  ПОЛНЫЕ СБРОСЫ · 3
#1  до 07.11, 06:07
#2  до 01.12, 02:32
#3  до 02.12, 05:12
```

> Пример макета, **не данные реального аккаунта**. Плагин показывает только те окна, которые действительно вернул OpenAI: например, у Pro может быть лишь недельный лимит.

## Возможности

- **Остаток и расход** 5-часового и/или недельного лимита, время сброса и обратный отсчёт.
- **Полные сбросы:** доступное количество и срок действия каждого, если OpenAI сообщил даты. Сбросы **не применяются** плагином.
- **Без мигания при переключении вкладок:** последний ответ хранится в памяти TUI; в обычном режиме повторный запрос выполняется не чаще раза в минуту. Устаревшие данные обновляются в фоне (проверка каждые 15 секунд), обратный отсчёт — локально каждые 30 секунд. При смене аккаунта кэш очищается и данные запрашиваются заново.
- Данные запрашиваются через серверный плагин; в TUI передаются только проценты, счётчики и даты — **не токены и не ID сбросов**.

## Установка

Нужны **OpenCode V2** с полноэкранным TUI и подключённый аккаунт OpenAI через ChatGPT/Codex OAuth. Подключение только через API-ключ не предоставляет квоты подписки. Для проверок и Git hooks также нужны Node.js/npm, Python 3 и Git.

1. Склонируй репозиторий в удобное место:

   ```bash
   git clone git@github.com:angrydish/opencode-openai-limits.git ~/opencode-openai-limits
   ```

2. Если собираешься коммитить или отправлять изменения, включи локальные проверки секретов **до первого коммита**:

   ```bash
   cd ~/opencode-openai-limits
   npm run security:hooks
   ```

   Для запуска тестов установи зависимости: `npm ci`. Git hooks работают без установки npm-пакетов, но требуют Python 3.

3. Добавь путь к каталогу в глобальный `~/.config/opencode/opencode.jsonc` (сохрани остальные настройки и уже существующие плагины):

   ```jsonc
   {
     "$schema": "https://opencode.ai/config.json",
     "plugins": ["/home/USER/opencode-openai-limits"]
   }
   ```

   Замени `USER` на своё имя пользователя. При `$XDG_CONFIG_HOME` глобальный файл находится в `$XDG_CONFIG_HOME/opencode/opencode.jsonc`. Если клонируешь в другой каталог, укажи его **абсолютный путь**.

4. Открой сессию в полноэкранном `opencode`. Конфигурация обновляется автоматически; если панель не появилась, выполни `/reload`. Правая панель должна быть видна (на узком терминале она может скрываться).

Если этот плагин уже подключён по другому локальному пути, **не добавляй его повторно**: оставь один действующий путь в конфигурации.

## Если что-то не отображается

| Симптом | Что проверить |
| --- | --- |
| Нет строки «5 часов» | У аккаунта может быть только недельное окно — так бывает у Pro. Окна определяются по длительности, а не по их порядку в ответе API. |
| Срок сброса «неизвестен» | OpenAI сообщил количество доступных сбросов, но не вернул их подробности. Даты не подставляются наугад. |
| `OpenAI 401` | Проверь активный аккаунт и способ авторизации. `chatgpt-token-sharing` может не давать доступа к API квот, даже если модели работают; попробуй вход **Codex browser (legacy)** или **Codex device code (legacy)**. |
| Панели нет в `mini` или Desktop | Плагин предназначен для **полноэкранного TUI** и его правой боковой панели. |

> **Важно:** `/backend-api/wham/usage` и `/backend-api/wham/rate-limit-reset-credits` — недокументированные API OpenAI. OpenAI может изменить формат или условия доступа. Плагин показывает ошибку или отсутствие данных вместо выдуманных процентов. Это квоты *подписки OpenAI*, а не бюджеты OpenCode Go/Console и не число токенов.

## Разработка

```bash
npm ci
npm test
npm run typecheck
npm run security:scan
npm audit
```

Серверный код и запросы к OpenAI — `src/index.ts`; разбор ответа — `src/usage.mjs`; боковая панель — `src/tui.tsx`; кэш — `src/cache.mjs`. Тесты не требуют доступа к аккаунту OpenAI.

## Защита секретов при публикации

В репозитории **не должны** находиться OAuth-токены, API-ключи, `.env`, файлы авторизации и приватные ключи. Токены плагин получает во время работы из активного подключения OpenCode; в Git их сохранять не нужно.

После клонирования включи локальные Git hooks (один раз для каждого клона; команда также приведена в установке):

```bash
npm run security:hooks
```

- `pre-commit` проверяет **проиндексированные версии** файлов (в том числе добавленные через `git add -f`), блокирует имена файлов с ключами и распространённые форматы секретов внутри файлов.
- `pre-push` проверяет **историю всех отправляемых коммитов**, включая секрет, удалённый последующим коммитом. В диагностике выводятся только тип находки и путь, не значение секрета.
- `npm run security:scan` запускает проверку текущей истории вручную.

Аудит истории репозитория не выявил секретных файлов или типичных токенов, но **это не доказательство отсутствия любых секретов**. `npm audit` на 8 ноября 2026 года выявил 26 предупреждений *moderate* в дереве зависимостей (в том числе транзитивных), без *high* или *critical*; они не устранены автоматически, чтобы не сломать совместимость с OpenCode. Перепроверяй отчёт после обновления зависимостей.

`.gitignore` помогает избегать ошибок, но **не защищает от принудительного добавления**. Локальные hooks — эвристика: они не включаются автоматически в других клонах, пропускают нестандартные секреты и обходятся через `--no-verify` или изменение `core.hooksPath`. В настройках GitHub по возможности включи серверные secret scanning и push protection; приватность репозитория сама по себе не заменяет эти меры. Если секрет всё же попал в Git, **сначала отзови/замени его**: простое удаление файла или коммит с удалением не убирают секрет из истории.
